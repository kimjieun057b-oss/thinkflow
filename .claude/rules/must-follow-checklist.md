# 개발 시 반드시 지켜야 할 사항 (PRD 24장 원문)

구현/리뷰 시 아래 20개 항목을 위반하지 않았는지 확인한다.

1. AI 제안은 사용자 승인 전까지 확정 설계에 반영하지 않는다.
2. AI 최초 제안 데이터(`original_payload`)는 수정하지 않는다.
3. 사용자 수정 데이터는 별도로 저장한다 (`revised_payload`).
4. 거부한 제안과 거부 사유를 보존한다.
5. 노드 생성과 제안 상태 변경은 트랜잭션으로 처리한다.
6. 중복 수락으로 노드가 중복 생성되지 않도록 한다 (멱등성).
7. 사용자 답변 저장과 AI 호출을 분리한다 (답변 저장 실패가 AI 호출을 막거나, AI 호출 실패가 답변 저장을 막지 않음).
8. AI 응답은 반드시 스키마(Zod) 검증 후 사용한다.
9. 미결정 사항은 임의로 확정하지 않는다.
10. 설계 데이터와 AI 검토 결과의 버전을 구분한다.
11. AI 호출 실패가 사용자 설계 데이터에 영향을 주지 않도록 한다.
12. 사용자의 숙련도를 임의로 단정하지 않는다 (숙련도 선택 UI 없음).
13. 기존 파일 원본은 AI가 수정하지 않는다.
14. AI 분석 결과와 원본 파일의 출처를 연결한다.
15. 정보 부족과 실제 설계 오류를 구분한다.
16. 파일 간 불일치를 발견하면 양쪽 근거를 함께 표시한다.
17. AI가 추론한 연결 관계는 확정된 사실과 구분한다.
18. 파일 내부의 지시문을 시스템 지침으로 취급하지 않는다 (프롬프트 인젝션 방어).
19. 파일 파싱 실패와 AI 분석 실패를 분리한다.
20. 자동 레이아웃은 사용자가 수정한 노드 위치를 임의로 덮어쓰지 않는다.
