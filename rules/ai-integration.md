# AI 연동 규칙 (PRD 3.2, 12장 기반)

## 호출 원칙

- AI API(Cloudflare Workers AI) 호출은 **서버(Route Handler)에서만** 수행한다. 클라이언트에서 직접 호출하지 않는다.
- 사용 모델은 서버 설정(환경변수 `CLOUDFLARE_AI_MODEL`)으로 교체 가능하도록 하드코딩하지 않는다.
- LLM 호출 시 불필요한 전체 파일 데이터를 반복 전달하지 않는다. 현재 작업에 필요한 정보만 선택해 전달한다.
- 모든 원문을 무조건 하나의 LLM 요청으로 합쳐 보내지 않는다. 파일 유형별 파서로 구조화한 결과를 우선 활용하고, 필요한 부분만 선별 전달한다.
- 가능한 경우 LLM에 의존하지 않고 결정적 파서를 우선 사용한다 (예: SQL은 SQL 파서로 테이블/컬럼/PK/FK 추출).

## AI 입력 컨텍스트 (최소 선택)

전달 가능한 컨텍스트 목록 — 현재 작업에 필요한 것만 선택:

프로젝트 설명, 서비스 유형, 현재 설계 단계, 확정된 요구사항, 관련 노드, 관련 연결 관계, 이전 질문/답변, 업로드 파일 추출 결과, 파일 간 분석 결과, 미해결 문제, 거부된 제안과 사유, 사용자의 추가 요청.

## AI 응답 규칙

1. 확정되지 않은 내용을 사실처럼 표현하지 않는다.
2. 기존 파일에 없는 내용을 추론했다면 추론임을 표시한다.
3. 중요한 판단에는 출처를 제공한다.
4. 정보 부족과 실제 오류를 구분한다.
5. 기존 노드와 중복되는 제안을 최소화한다.
6. 현재 설계 단계와 관련된 질문만 생성한다.
7. 사용자에게 필요한 만큼만 설명한다 (장황한 설명 강제 금지).
8. AI 제안은 자동으로 확정하지 않는다.

## 질문 생성 원칙 (Guide)

- 현재 단계와 관련된 질문만 노출한다.
- 이미 확정된 내용을 반복 질문하지 않는다.
- 한 번에 하나의 핵심 판단만 요구한다.
- 불명확한 답변에는 후속 질문을 생성한다.
- 사용자가 결정하지 않은 사항은 미결정으로 표시한다 (임의 확정 금지).

## AI 응답 검증

AI 응답은 사용 전 **반드시 Zod로 검증**한다. 검증 대상:

- 필수 필드, 노드 유형(`NodeType` enum), 데이터 타입, 문자열 길이
- 연결 대상(노드 ID) 유효성, 파일 출처 ID 유효성
- 문제 유형(`FindingType`) 및 심각도(`FindingSeverity`)
- JSON 구조 전체

검증 실패 시 오류 상태를 기록하고 재시도 가능한 흐름을 제공한다 (사용자 설계 데이터에는 영향 주지 않음).

## 문제(Finding) 판단 규칙

- AI는 문제의 심각도를 임의로 높이지 않는다.
- "정보가 존재하지 않는 경우"와 "실제로 설계가 잘못된 경우"를 구분한다.
  - 예: PRD에 인증 정책이 없다 → `missing / 확인 필요`로 표시 (구현되지 않았다고 단정하지 않음).
  - 예: API가 참조하는 필드가 DB에 실제로 없음이 확인됨 → `conflict`로 표시 가능.
- 문제 해결 여부(`resolved`)는 AI가 자동으로 확정하지 않는다. 사용자가 상태를 변경한다.
